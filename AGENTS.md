# AGENTS.md — The Vault (canonical agent instructions)

These instructions apply to ANY AI agent working in this vault (Claude Code, Codex, Hermes, or any future tool). Agent-specific additions live in that agent's own file (e.g. `CLAUDE.md`), which imports or points to this file — never duplicate it.

## Privacy Rules — ABSOLUTE, NO EXCEPTIONS

1. Never enter, read, or reference any file inside `3 - Journal`
2. If a file has `private: true` in frontmatter → treat as non-existent

That is the whole list. These two rules override everything else, always — including
"not to memory": no journal or `private: true` content ever enters the knowledge graph,
the semantic index, or agent memory.

They are enforced in code, not by convention. `0 - System/scripts/privacy_guard.py` is
the single implementation, and every runtime's pre-tool hook is a thin wrapper around it
(`.claude/privacy-guard.py`, `~/.hermes/agent-hooks/privacy-guard.py`). It blocks rule 1
anywhere in a tool payload, and rule 2 for any call naming a single resolvable file.
A Bash or Grep call names no single file, so rule 2 cannot be checked there — that gap is
covered by the script-level filters in `vaultlib.py`, `gen_graphifyignore.py` and
`embed_index.py --audit`.

A filename starting with `_` is a **generated system file, not a secret** — skip it when
indexing or compiling, but it is readable. (`7 - Wikipedia/_cache.md` is required reading
at session start; a rule that blocked `_` files contradicted that and broke the ambient
agent.)

## Core Files — AIOS Layer 2 (read for context, do not duplicate)

These files hold the portable identity, navigation, and skill catalog. Point to them; don't restate their contents here.

- `0 - System/me.md` — who the user is, how they think, how they want AI to work with them.
- `0 - System/vault-map.md` — folder map, privacy gates, output routing.
- `0 - System/skills-index.md` — catalog of all skills + each trigger (single source of truth).

## Vault Structure

- `0 - System/` — system config files. Never modify, EXCEPT the agent-managed subfolders:
  - `0 - System/memories/` — agent memory (Hermes `USER.md`/`MEMORY.md` live here; `~/.hermes/memories` is a symlink to this folder). Agents read AND write here. Not published — see the README there.
  - `0 - System/hermes-skills/` — generated agentskills.io-format skills, loaded live by Hermes via `skills.external_dirs`. Regenerated by `scripts/sync_skills_to_hermes.py --apply`; do not hand-edit (edit the source `SKILL-*.md` instead).
  - `0 - System/agents/` — portable subagent/persona prompts (e.g. wiki-librarian).
- `1 - Topics/` — promoted notes with many references. Do not auto-compile.
- `2 - Notes/` — the user's notes and summaries they explicitly requested.
- `3 - Journal/` — completely off limits. Never touch.
- `4 - Templates/` — templates only. Do not modify.
- `5 - Tables/` — do not modify.
- `6 - Images/` — do not modify.
- `7 - Wikipedia/raw/` — raw source material. Never modify these files.
- `7 - Wikipedia/` — compiled wiki pages. You write and maintain these.
- `7 - Wikipedia/index.md` — master catalog. Update after every ingest.
- `7 - Wikipedia/log.md` — append-only history. Log every operation.
- `7 - Wikipedia/.manifest.json` — tracks every ingested source.
- `7 - Wikipedia/_cache.md` — hot cache from last session. Read at start, update at end.
- `7 - Wikipedia/raw/youtube_queue.md` — YouTube videos queue for compilation. Updated automatically after each ingest.

## Retrieval Indexes — derived, never the source of truth

Two indexes sit on top of the markdown. Both are regenerable and both are gitignored,
because each one enumerates real note paths:

- `graphify-out/` — the knowledge graph. Answers **how things connect**.
- `vector-out/` — the semantic index (bge-m3 via local Ollama). Answers **what things mean**:
  meaning-based search that crosses languages and reaches notes and topics, not just the wiki.

The markdown is the truth. Delete either index and rebuild it at any time.

## Frontmatter Convention

`0 - System/SCHEMA.md` is the single source of truth for the allowed values.
`0 - System/scripts/validate.py` enforces this section.

**Three axes — each answers exactly one question:**

- `type:` — *what kind of object is this.* Required (the one field OKF mandates).
  One of: `wiki-page`, `note`, `topic-hub`, `template`, `checklist`, `report`, `index`, `log`.
- `subject:` — *which area of life this belongs to.* Wikilink, only subjects defined in SCHEMA.md.
  If none fits → **leave empty**. That is correct and intended, not a gap.
- `tags:` — *what the file is for.* Only tags declared in SCHEMA.md. **Never a leading `#`**
  (Obsidian Bases treats `ai` and `#ai` as two different values and splits every grouped view).

**Also on every file:**

- `background:` — one-line description. Doubles as the cross-language bridge for semantic
  search, so keep it meaningful.
- `private:` — if true, the file does not exist as far as you are concerned.
- `created:` — creation timestamp.

**OKF v0.2 trust layer:**

- `generated_by` / `generated_at` — who produced it and when. Actors: `human:<name>`,
  `process:<name>`, or `<agent>/<version>`. Two flat keys, **never** a nested `generated:`
  map — Obsidian Properties renders only flat scalars and lists.
- `verified: [{by, at}]` — who *reviewed* it. **Absent = unverified**; write it only via `okf_verify.py`.
- `status:` — `draft` / `stable` / `deprecated`. **Absent = `stable`**, so only write it when it isn't.
- `wiki_sources:` — this vault's equivalent of OKF `sources`; provenance links on compiled pages.

Adding a key OKF doesn't require, or restating a default, is churn — don't.

**Extension rule:** a new subject or tag goes into SCHEMA.md *first*, then gets used.
Never invent one inline — `validate.py` will fail, which is the point.

Language of frontmatter values: follow the user's language in the request.
Exception: agent-managed files in `0 - System/memories/` keep their agent-native format
(Hermes `§`-card format), and `0 - System/hermes-skills/**` use the agentskills.io schema —
neither takes vault frontmatter.

## Skills — Lazy Loading

Do NOT pre-load skill files. Read the relevant skill only when the request requires it:

- Ingest new sources → read `0 - System/SKILL-ingest.md`
- Resolve and update existing pages → read `0 - System/SKILL-resolve.md`
- Answer questions → read `0 - System/SKILL-query.md`
- Search by meaning, not keyword → read `0 - System/SKILL-vsearch.md`
- Health check → read `0 - System/SKILL-lint.md`
- Check status → read `0 - System/SKILL-status.md`
- Cross-link pages → read `0 - System/SKILL-crosslink.md`
- Publish the public mirror → read `0 - System/SKILL-publish.md`

If no skill matches the request → proceed with general judgment and note the absence.

## Output Rules

- Compiling external sources → `7 - Wikipedia/`
- A summary explicitly requested → `2 - Notes/`
- Every created file gets full frontmatter (see Frontmatter Convention).

## Session Rules

**At session start — read only these files:**

1. `0 - System/hooks.json` — required for automated session behavior
2. `7 - Wikipedia/_cache.md` — recent context from last session

Do NOT read other files in `0 - System/` unless a specific skill or operation requires them.

**At session end:**

- Update `7 - Wikipedia/_cache.md` with a summary of what was done.

## Conventions

- Use [[wikilinks]] for all internal links
- Language: follow the user's language in the request
- The user's own ideas stay in Notes and Topics — never move them to Wikipedia
- Never create new subjects not defined in SCHEMA.md
- Never invent new tags
- If no suitable tag or subject exists → leave the field empty

## Engines & Models

- Heavy/deep work: Claude Code, directly in this vault.
- Ambient work: Hermes — default model via one provider (e.g. OpenAI Codex); `/model local` switches to on-device Ollama for private/sensitive content. Model switching = one alias per provider in `~/.hermes/config.yaml` (`model_aliases`).
- Claude never runs inside Hermes (subscription ToS); Anthropic credentials are kept outside `~/.hermes` entirely.
- Swapping agents later: point the new agent at this file + `0 - System/{hermes-skills, memories, agents}`.

## Context Health
- If the conversation exceeds ~80 messages or you feel uncertain about earlier context, say: "⚠️ Context may be degrading — consider /clear"
- When asked about something from early in the session, say explicitly: "Based on what I can see in context..."
- Never invent details about files or decisions not currently visible
